## 📋 Описание проекта

Консольная симуляция банкомата на C++17. Система поддерживает базовые банковские операции, персистентное хранение данных и восстановление состояния после сбоев через бинарный журнал транзакций.

## ⚙️ Функциональность

### Операции
- 💳 **Вставка карты** и проверка её наличия в базе
- 🔐 **Ввод PIN** с защитой от перебора (блокировка после 3 неверных попыток)
- 💰 **Проверка баланса**
- ➕ **Пополнение счёта**
- ➖ **Снятие наличных** с автоматическим расчётом комиссии
- 📜 **История операций** (последние 5 транзакций)
- 🚪 **Завершение сессии**

### Лимиты и комиссии
- Максимальная сумма за одно снятие: **10 000 руб.**
- Суточный лимит снятий: **50 000 руб.**
- Комиссия за снятие: **1%**, минимум **30 руб.**

## 🔄 Crash Recovery

Ключевая особенность системы — устойчивость к сбоям. При каждом запуске `Recovery::restore_state()` читает бинарный журнал `atm_journal.bin` и воспроизводит все транзакции, восстанавливая актуальные балансы счетов — без необходимости в отдельной БД.

```
Запуск → читаем atm_journal.bin → replay всех транзакций → актуальное состояние ✅
```

Транзакция записывается в журнал сразу после выполнения с `flush()`, что гарантирует сохранность даже при крэше.

## 🗂️ Структура данных

### `Transaction` (бинарная, фиксированный размер)
```cpp
struct Transaction {
    char card_number[17];   // 17 байт
    TransactionType type;   // 1 байт (enum uint8_t)
    double amount;          // 8 байт
    double fee;             // 8 байт
    int64_t timestamp;      // 8 байт (Unix time)
};
```

### `cards_db.txt` (текстовый)
```
<номер_карты> <PIN> <заблокирована> <попытки>
1234123412341234 1111 1 3
5555555555555555 1111 0 0
```

## 🛠️ Сборка и запуск

### Требования
- Компилятор с поддержкой **C++17** (g++ 7+, clang++ 5+)
- CMake 3.10+ (опционально) или прямая компиляция

### Компиляция через g++
```bash
g++ -std=c++17 -o atm_system \
    main.cpp atm_engine.cpp account.cpp card.cpp \
    journal.cpp file_storage.cpp recovery.cpp
```

### Запуск
```bash
./atm_system
```

При первом запуске создаётся пустой журнал `atm_journal.bin`. Файл `cards_db.txt` должен лежать рядом с исполняемым файлом.

### Тестовые карты

| Номер карты | PIN | Статус |
|-------------|-----|--------|
| `5555555555555555` | `1111` | ✅ Активна |
| `1234123412341234` | `1111` | 🔒 Заблокирована |

## 🐛 Известные ограничения

- `FileStorage::save_cards()` сохраняет PIN как хардкод `"1111"` вместо реального значения — PIN не персистируется корректно между запусками при изменении.
- Отсутствует шифрование PIN: хранится в открытом виде в `cards_db.txt`.
- Суточный лимит привязан к Unix-дням (UTC), часовой пояс пользователя не учитывается.
- История ограничена последними 5 операциями в памяти (за сессию).

---

## 📚 Использованные концепции

- **RAII** — `Journal` открывает файл в конструкторе, закрывает в деструкторе
- **Unique_ptr** — владение `Journal` и `FileStorage` без утечек памяти
- **Crash Recovery / WAL** — идея Write-Ahead Log из мира СУБД
- **Append-only log** — журнал только дополняется, не перезаписывается
- **POD-сериализация** — прямая запись структуры в бинарный файл
